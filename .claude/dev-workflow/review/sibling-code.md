---
title: 新しく書いた処理に、同じ目的の既存の処理があるのに、別の書き方になっていないか
paths: ["!docs/**"]
---

差分で新しく書いた処理（関数・スクリプトの一節・テストの補助）ごとに、リポジトリの中に同じ目的の既存の処理がないかを探し、あれば書き方が揃っているかを確かめる。

確かめ方：
1. 差分で追加・変更した処理が何をするか（例：Project の項目を探す、Issue を読む、エラーを整形する）を、1文で言い表す。
2. 同じことをしている既存の処理を、`grep` などでリポジトリ（`plugins/`・`tests/`）から探す。呼ぶコマンド（`gh api`・`gh project` など）、関数名、同じ意味のコメントや変数名で探す。
3. 見つかったら、差分の処理と比べて、次のどれかが食い違っていないかを見る。
   - 使う API やコマンド（既存が REST なのに、新しい方は別の手段を使っている、など）
   - 上限・ページング・エラーの扱いなど、既存が前提にしている条件
   - 既存のコメントに書かれた理由（その手段を選んだ理由、避けている手段）
4. 既存の処理をそのまま呼べる、または共通の関数にまとめられるのに、似た処理が増えていないかも見る。

指摘には、差分の処理（ファイルと行）、揃えるべき既存の処理（ファイルと行）、どこが食い違っているか、どう揃えるか（既存を呼ぶ・共通の関数にする・既存に合わせて直す）を挙げる。

指摘しないこと：
- 同じ目的の既存の処理が見つからないもの
- 見た目や命名の好み
- 食い違いに正当な理由があるもの（差分や既存のコメントに理由が書かれているときは、その理由が成り立つかだけを見る）
- 差分が変えていない既存の処理の問題

当てはまる処理が差分に無ければ、指摘は出さない。
