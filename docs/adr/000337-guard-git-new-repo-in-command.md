# guard-git は、同じコマンドの中で git init・git clone で作るリポジトリを、作り方で見分けて判断する

## 背景と課題

[ADR 000219（guard-git の対象のリポジトリ）](000219-resolve-guard-git-target-repo.md) の追補（#238）で、git が対象のリポジトリを見つけられないときは、今のブランチを読めないので、コミットと push 先を書かない push を止めることにした。ところが、フックはコマンドを実行する前に動くので、`git init proj && cd proj && git commit` のように、同じコマンドの中で作るリポジトリも「見つけられない」ことになり、止まっていた。止めたときの案内（絶対パスの `cd`・`git -C`）では、まだ無いディレクトリを指せない（#314）。一方で、`mkdir d && cd d && git commit` は、git が外側のリポジトリ（base_branch の上かもしれない）でコミットするので、通すと守りが外れる。

## 検討した案

* 作る場所を覚え、`git init` で作るリポジトリは導入していないものとして通し、`git clone` するリポジトリは対象が分からないものとして止める
* その git の呼び出しより前に `git init`・`git clone` があれば、どこに作るかを問わず通す
* 今までどおり、すべて止める

## 判断の結果

選んだ案：「作る場所を覚え、`git init` は通し、`git clone` は対象が分からないものとして止める」。理由は、`git init` で作ったばかりのリポジトリにはチームの設定が無く、ADR 000219（効く範囲）の決まりどおり導入していないリポジトリとして扱えるが、`git clone` するリポジトリは、導入したリポジトリ（チームの設定をコミットしたもの）かもしれず、ブランチも分からないため。前に `git init`・`git clone` があれば通す案は、導入したリポジトリを clone して base_branch の上でコミットする書き方を通してしまう。

* 作る場所は、`git init [<ディレクトリ>]` のディレクトリ（無ければ git を実行する場所）と、`git clone <リポジトリ> [<ディレクトリ>]` のディレクトリ（無ければ、git と同じくリポジトリの名前から決める）。`git -C` で指した場所から解決する。`--git-dir`・`GIT_DIR` などがあると作る場所が変わるので、覚えない。
* まだ無いディレクトリへの `cd`・`git -C`・`env -C` は、今までは移った先を不明としていたが、あるところまでを実体にしたパスとして追う（そのパスでは git がリポジトリを見つけられないので、作る場所に当たらなければ、今までどおり対象が分からないものとして扱う）。
* 作る場所とその下で動く git は、`git init` なら何もしない。`git clone` なら対象が分からないときと同じに扱い、clone を先に実行してから別のコマンドで操作するよう案内する。
* 既にあるリポジトリのルート（bare なら git のディレクトリ）での `git init` は、作り直すだけで中身は変わらないので、覚えずに今までどおりそのリポジトリで判断する。既にあるディレクトリでも、リポジトリのルートでなければ、`git init` は新しいリポジトリを作るので、作る場所として覚える。
* `mkdir` だけで作るディレクトリへの `cd` の後は、今までどおり対象が分からないものとして止める。

### 結果として起きること

* 良い点：同じコマンドの中で `git init` してからコミットする書き方が止まらない。
* 良い点：導入したリポジトリを clone して base_branch の上でコミットする書き方は、今までどおり止まる。
* 悪い点：導入していないリポジトリの clone でも、同じコマンドの中では、移った後のコミットが止まる（clone を別のコマンドに分ければ通る）。
* 悪い点：`git init` の後に、同じコマンドの中でチームの設定を作ってコミットしても、導入していないものとして通す（同じコマンドの中で導入まで済ませる書き方はまれで、最後の守りは GitHub のルールセットのため）。

## 補足

* [ADR 000219（guard-git の対象のリポジトリ）](000219-resolve-guard-git-target-repo.md) の追補（#238）の「git がリポジトリを見つけられないときは止める」に、同じコマンドの中で作るリポジトリの扱いを足す。それ以外の決まりは変えない。
* 出典：Issue #337（https://github.com/nakayama-labs/agent-plugins/issues/337）。元の Issue は #314（https://github.com/nakayama-labs/agent-plugins/issues/314）。
* `tests/guard-git.bats` で、`git init` で作る場所（cd・`git -C`・既にあるディレクトリ・作り直し）、`git clone` する場所（名前の決め方を含む）、`mkdir` だけの場所を確かめる。
