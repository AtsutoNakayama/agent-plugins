# このリポジトリをプラグインマーケットプレイスにし、dev-workflow の1つのプラグインにまとめて配る

## 背景と課題

全リポジトリで共通に使う Claude Code のスキル群と、GitHub の初期設定スクリプトを、どの形で配るかを決める必要があった。リポジトリごとに違う値（Project の番号、列名など）もあり、チームの各リポジトリで同じものを使えるようにしたい。

この判断は初期の設計（`docs/design.md` の最初の版、2026-09-23）でしたもので、判断のための Issue は無い。設計の段階 0（マーケットプレイスとプラグインの骨組み）を実装した Issue #1 の番号を使う。

## 検討した案

* マーケットプレイスに1つのプラグイン（dev-workflow）としてまとめ、初期設定のスクリプトもプラグインの中に置く
* 初期設定のスクリプトを、プラグインの外（リポジトリ直下の `scripts/`）に置く（最初の設計書の形）
* 用途ごとに複数のプラグインに分ける（例：レビューだけのプラグイン）

## 判断の結果

選んだ案：「マーケットプレイスに1つのプラグイン（dev-workflow）としてまとめ、初期設定のスクリプトもプラグインの中に置く」。

* このリポジトリを公開のプラグインマーケットプレイス（`.claude-plugin/marketplace.json`）にする。リポジトリごとに違う値は設定ファイルに外出しする。
* プラグインは `dev-workflow` の1つにまとめる。レビューだけ使いたい人が出てきたら、分割を検討する。
* チームに配るときは、対象リポジトリの `.claude/settings.json` に `extraKnownMarketplaces` と `enabledPlugins` を書く。
* スキルから呼ぶものは、初期設定用のスクリプトも含めて、すべてプラグインの中に置く。プラグインとして入れると、プラグインのディレクトリの外にあるファイルはキャッシュにコピーされず使えないため（最初の設計書では初期設定のスクリプトを外の `scripts/` に置いていたが、同じ日にプラグインの中の `scripts/setup/` へ移した。どのプラグインのものか分からなくなるリポジトリ直下の `scripts/` もなくした）。

### 結果として起きること

* 良い点：プラグインを1つ入れれば、スキル・フック・初期設定のスクリプトがそろう。repo-setup スキルから初期設定のスクリプトを呼べる。
* 配布の対象は `plugins/dev-workflow/` の中だけになり、外（`.github/`・`tests/`・`docs/` など）はこのリポジトリ専用になる（CONTRIBUTING.md の「スキルから呼ぶファイルは `plugins/dev-workflow/` の中に置きます」）。

### 確認

`claude plugin validate --strict .`（マーケットプレイス）と `claude plugin validate --strict plugins/dev-workflow`（プラグイン本体）を CI で実行する。スキルから呼ぶファイルがプラグインの外を参照していないかは、レビューで確かめる。

## 補足

* 出典：設計書の最初の版（ff4b714）、コミット 5b82797（初期設定のスクリプトをプラグインの中へ移す）、Issue #1（https://github.com/nakayama-labs/agent-plugins/issues/1）
* 複数のプラグインに分ける案は、使う人がいないうちは採らず、「レビューだけ使いたい人が出てきたら」見直す。
* 1つにまとめた理由は、設計書に書かれた「レビューだけ使いたい人が出てきたら分割を検討する」以外には残っていない。
