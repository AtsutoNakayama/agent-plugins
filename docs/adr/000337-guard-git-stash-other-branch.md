# 別のブランチで作った stash の取り出し・破棄を、guard-git で止める

## 背景と課題

stash（`refs/stash`）は、リポジトリの全ワークツリーで共有される。#320 の作業で、作業役が `git stash` と `git stash pop` を使ったとき、別のワークツリーの作業（#248 に関係するとみられる）が作った stash を取り出し、その変更が #320 のワークツリーに混ざった（#324）。複数のワークツリーで並行して作業する流れ（task-start がワークツリーを作る）では、同じことがまた起きうる。別の作業の stash を、取り出す・消すのをどう防ぐか。

## 判断の決め手

* 並行して作業する Claude が、手順を読み落としても防げること
* 自分の作業で作った stash は、今までどおり使えること
* 止めたときに、何をすればよいかが1行で分かること
* 導入していないリポジトリには効かないこと（[ADR 000219](000219-limit-scope-to-set-up-repos.md)）

## 検討した案

* guard-git（PreToolUse のフック）で、取り出す・消す stash を作ったブランチが今のブランチと違えば止める
* タスクの進め方（task-flow が渡す文章）に、別のブランチの stash を取り出さないよう書いて縛る
* stash の使用そのもの（`git stash` を含む）を、フックで止める

## 判断の結果

選んだ案：「guard-git で、取り出す・消す stash を作ったブランチが今のブランチと違えば止める」。理由は、文言で縛る案は読み落とすと防げず、stash をすべて止める案は自分の作業の stash まで使えなくなるため。

* `git stash pop`・`apply`・`drop`・`branch` は、対象の stash（書かなければ `stash@{0}`、数だけなら `stash@{<数>}`）の件名（`WIP on <ブランチ>: …`・`On <ブランチ>: …`）のブランチが、操作の対象のリポジトリの今のブランチと違えば止める。detached HEAD で作った stash の件名は `(no branch)` になり、別のワークツリーの detached HEAD と見分けられないので、今も detached HEAD のときは、stash を作ったときの HEAD（stash のコミットの1つ目の親）が今の HEAD と同じときだけ通す。件名からブランチが読めないときも、違うものとして止める。
* `git stash clear` は、全ワークツリーの stash をすべて消すので、いつも止める（今のブランチの stash を `git stash drop` で1つずつ消すよう案内する）。
* 対象の stash を読めない（無い）ときは、git 自身が失敗するので通す。今のブランチを読めない（対象のリポジトリが分からない）ときは、比べられないので止める（コミットと同じ。[ADR 000219](000219-resolve-guard-git-target-repo.md) の追補）。
* `git stash`（push）・`list`・`show` など、作る・見るだけの操作は止めない。

### 結果として起きること

* 良い点：別のワークツリーの作業が作った stash を、取り出す・消すことが無くなる。
* 良い点：同じブランチで作った stash は、今までどおり取り出せる。
* 悪い点：同じブランチ名を、別のワークツリーで使い回したとき（消して作り直したブランチなど）は、見分けられない。
* 悪い点：別のブランチの stash を、わざと取り出したいときも止まる。そのときは、使用者が自分で実行する（フックは Claude Code の Bash にしか効かない）か、stash を作ったブランチで取り出す。
* 悪い点：件名を変えた stash（`git stash store -m` で独自の件名にしたものなど）は、ブランチを読めないので止まる。

### 確認

`tests/guard-git.bats` で、別のブランチ・別のワークツリーで作った stash の `pop`・`apply`・`drop`・`branch`（省略・番号・`stash@{N}`）を止め、理由が1行であること、今のブランチの stash は通すこと、`clear` はいつも止めること、作る・見るだけの操作と無い stash は止めないこと、導入していないリポジトリでは止めないことを確かめる。

## 各案の長所と短所

### guard-git で、作ったブランチが違えば止める

* 良い点：手順を読み落としても防げる。
* 良い点：自分の作業の stash は使える。
* 悪い点：件名を頼りにするので、ブランチ名の使い回しや、件名を変えた stash は見分けられない。

### タスクの進め方の文言で縛る

* 良い点：フックを変えずに済み、わざと取り出したいときも止まらない。
* 悪い点：読み落とすと防げない（#324 は、手順の文言があっても起きうる種類の誤り）。
* 悪い点：Claude Code の外から渡した指示（作業役への指示など）では、文言が届かないことがある。

### stash の使用そのものを止める

* 良い点：仕組みが単純で、取り違えは起きない。
* 悪い点：自分の作業で、一時的に変更を退けることもできなくなる。
