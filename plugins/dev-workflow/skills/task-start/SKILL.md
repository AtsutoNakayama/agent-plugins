# 作業の開始

Issue の作業を始められる状態にする。ブランチ名の短い説明は AI が考え、ワークツリーの作成・割り当て・列の移動は `task-start.sh` が行う。

「#12 に着手して」という依頼で結果が決まり、割り当てと列の移動は戻せるので、実行の確認は取らずに進めて結果を伝える（設計書 §8）。ただし、Issue のラベルを直すときは確認を取る。

スクリプト（どれも JSON を出力する）:

- `${CLAUDE_PLUGIN_ROOT}/scripts/task-start.sh`：ワークツリーとブランチの作成・割り当て・列の移動（`--help` で使い方）
- `${CLAUDE_PLUGIN_ROOT}/scripts/branch-name.sh`：ブランチ名を作る・検証する（task-start.sh が中で使う）

## 手順

### 1. Issue を読む

引数があれば Issue の番号として使う（`12` でも `#12` でもよい）。引数が無ければ、依頼の文章から番号を読む。それでも分からなければユーザーに聞く。`gh issue view <番号> --json number,title,body,labels,state` で Issue を読む。閉じていれば止める。type ラベル（`labels.types` のどれか）が無い、または複数あるときは、どれにするかユーザーに聞いて Issue のラベルを直してから進める（ラベルの変更も確認を取ってから行う。選択肢の説明には「Issue #12 のラベルを fix だけにする」のように、選ぶと何が変わるかを書く）。

### 2. ブランチ名の短い説明を考える

Issue のタイトルと本文から、何をするかが分かる**英語の**短い説明を考える（2〜5語。例：`add login page`）。日本語は使わない（ブランチ名は `[a-z0-9-/]` だけ）。

### 3. 実行する

`task-start.sh --issue <番号> --slug "<短い説明>"` を実行する。実行の前に AskUserQuestion で確認を取らない。

「短い説明に英数字がありません」で止まったら、手順2に戻って英語の短い説明を考え直し、もう一度実行する。

ほかのエラーで失敗したら、標準エラーの1行のメッセージをそのまま伝える。途中で失敗しても、もう一度実行すれば既にあるワークツリー・割り当てを使い回して続きから進む。サブモジュールの初期化に失敗したときは、警告（`warn:`）を出すだけで続ける。その警告もユーザーに伝える。

### 4. 結果を伝える

ブランチ名とワークツリーの場所（`worktree`）、列（`status.to`）を伝える。以後の作業は、そのワークツリーの中で行う（Bash では `cd <worktree>` してから作業する）。

実装は、全部を直し終えてから1回でコミットするのではなく、論理的な区切り（1つの変更を仕上げてテストが通ったところ）ごとに commit スキルでコミットしながら進める。区切りの細かさは commit スキルの手順2の基準に従う。
