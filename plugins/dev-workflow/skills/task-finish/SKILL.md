# 作業の後片付け

PR がマージされた作業のワークツリーとローカルのブランチを削除し、マージ先のブランチ（`base_branch`）を最新にする。マージの確認・削除・更新は `cleanup.sh` が行う。

ワークツリーとブランチの削除は取り消しにくいので、必ず手順2でユーザーの承認を得てから行う（設計書 §8）。承認なしに `--dry-run` を外して実行しない。

スクリプト（JSON を出力する）:

- `${CLAUDE_PLUGIN_ROOT}/scripts/cleanup.sh`：マージの確認、ワークツリーとブランチの削除、`base_branch` の更新（`--help` で使い方）

## 手順

### 1. 片付けるブランチを決める

- 今いるのが作業用のブランチ（ワークツリーの中など）なら、そのブランチ
- Issue の番号を言われたら、`git worktree list` と `git branch --list '*/<番号>-*'` でそのブランチを探す。見つからない、または複数あるときはユーザーに聞く

### 2. 予定を見せて確認を取る

`cleanup.sh --branch <ブランチ> --dry-run` を実行し、PR（`pr.number`・`pr.url`）と `actions`（削除するワークツリー・ブランチ、`base_branch` の更新）を見せる。AskUserQuestion で「この内容で片付ける」「やめる」などを選んでもらう。会話の中のあいまいな返事を承認とみなさない。

dry-run が止まったときは、標準エラーの1行のメッセージをそのまま伝えて終える。削除のために変更を捨てたり、強制したりしない。

- 「まだマージされていません」「マージされた PR がありません」：マージされてから片付ける
- 「PR に入っていないコミットがあります」：push していない作業が無いかユーザーに確かめてもらう
- 「未コミットの変更があります」：コミットするか、要らなければユーザーに片付けてもらう
- 「サブモジュール（…）に、リモートに無いコミットか stash があります」：サブモジュールのリモートに push するか、要らなければユーザーに片付けてもらう。リモートのブランチ・タグに無いコミットを SHA で取ってきただけのときも止まるので、そのコミットが要らないことをユーザーに確かめてもらってから、ユーザーにワークツリーを消してもらう

### 3. 実行する

承認されたら、削除するワークツリーの外に出てから（Bash では `cd <main_root>`）、同じ引数で `--dry-run` を外して実行する。ワークツリーの中にいたままだと、削除した後に今の場所が無くなる。

失敗したら、標準エラーの1行のメッセージをそのまま伝える。途中で失敗しても、もう一度実行すれば既に削除したものを飛ばして続きから進む。

### 4. 結果を伝える

削除したワークツリー（`worktree`）とブランチ、`base_branch` の更新（`base.from` → `base.to` の短い sha）を伝える。以後の作業はメインのワークツリー（`main_root`）で行う。
