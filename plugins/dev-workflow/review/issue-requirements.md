---
title: 変更が Issue の「やること」と「完了条件」を満たし、範囲外の変更が混ざっていないか
issue: required
---

この観点は、Issue があるときだけ実行される（frontmatter の `issue`）。Issue が有るかどうかは判断し直さない。

作業中の Issue（渡された番号を `gh issue view <番号>` で読む）と差分を突き合わせて、次を確かめる。

- 「やること」のチェックリストの各項目が、差分で実際に行われているか。行われていない項目があれば、どの項目かを挙げる
- 「完了条件」を満たしているか。差分だけでは確かめられない条件（CI が通る、動作を確かめた など）は指摘にせず、確かめ方を添えて「未確認」として挙げる
- Issue の範囲に無い変更（関係の無いリファクタリング・別の不具合の修正・ついでの整形など）が混ざっていないか。混ざっていれば、別の Issue に分けるべきかを指摘する。ただし、レビューの観点ファイル（`.claude/dev-workflow/review/*.md`）の追加・修正は、きっかけになったタスクの PR に含める決まりなので、範囲外として指摘しない

`gh issue view` で Issue を読めない（認証・通信など）ときは、指摘を出さずに「Issue を読めないので確かめられない」とだけ返す。
