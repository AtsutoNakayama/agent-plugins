---
title: 不具合の修正に、その不具合がもう一度起きないことを確かめるテストがあるか
types: [fix]
---

この観点は、変更の type が `fix`（不具合の修正）のときだけ実行される（frontmatter の `types`）。不具合の修正かどうかは判断し直さず、不具合の修正として確かめる。

次を確かめる。

- その不具合を再現するテストが、差分で追加または更新されているか
- そのテストが修正前のコードでは失敗するか。テストは実行せず、テストの入力と期待する結果が、直した箇所の振る舞いを確かめているかを、修正の前後のコードと見比べて判断する。修正と関係の無い箇所しか確かめていないテストや、修正前のコードでも通るテストは、テストが無いのと同じに扱う
- テストが無い・足りないときは、どのテストファイルに、どんな入力・状況で、何を期待するテストを足すべきかを具体的に挙げる

テストで確かめられない修正（ドキュメントの誤字、テストの仕組みの外にある設定など）は指摘にしない。
