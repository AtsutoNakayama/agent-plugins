---
title: 不具合の修正に、その不具合がもう一度起きないことを確かめるテストがあるか
---

まず、差分が不具合の修正かどうかを確かめる。次のどれかに当たれば不具合の修正とみなす。

- ブランチ名の type が `fix`（例：`fix/12-...`）
- ブランチのコミットに type が `fix` のもの（`fix:`・`fix(<scope>):`）がある
- 作業中の Issue（ブランチ名の番号から `gh issue view <番号>` で読む）に `fix` ラベルがある、または本文が不具合を扱っている

不具合の修正でなければ、指摘を出さずに「不具合の修正ではないので対象外」とだけ返す。

不具合の修正なら、次を確かめる。

- その不具合を再現するテストが、差分で追加または更新されているか
- そのテストが修正前のコードでは失敗するか。テストの入力と期待する結果が、直した箇所の振る舞いを確かめているかを読んで判断する。修正と関係の無い箇所しか確かめていないテストや、修正前でも通るテストは、テストが無いのと同じに扱う。確かめられるときは、ベースのブランチから作った一時的なワークツリーに追加したテストだけを持ち込んで実行し、失敗することを確かめる
- テストが無い・足りないときは、どのテストファイルに、どんな入力・状況で、何を期待するテストを足すべきかを具体的に挙げる

テストで確かめられない修正（ドキュメントの誤字、テストの仕組みの外にある設定など）は、理由を添えて「テストを足せない修正」として挙げ、指摘にはしない。
