---
title: ブランチを作った後にマージ先に入った変更と、このブランチの変更が食い違っていないか
base_ahead: required
---

この観点は、マージ先が基点より進んでいる（ブランチを作った後にマージ先へコミットが入った）ときだけ実行される（frontmatter の `base_ahead`）。進んでいるかどうかは判断し直さない。

ブランチを作った後にマージ先のブランチに入った変更を読み、このブランチの変更がそれに追随できているかを確かめる。テキストとしては衝突せずにマージできても、マージした後に壊れる変更を見つけるのが目的。

1. マージ先は、依頼に書かれたマージ先（`origin/<ブランチ>` の形の ref。開いた PR があればそのマージ先で、設定の base_branch と違うことがある。review スキルが `merge-target.sh` で決めて取得したもの）を使い、自分で決め直さない。`git log --oneline --no-show-signature <基点>..<マージ先>` と `git diff <基点> <マージ先>` で、ブランチを作った後に入った変更を読む。依頼にマージ先が無ければ、確かめられないことを `notes` に書いて終える
2. その変更のうち、ほかのコードが依存しうるものを拾う
   - 名前の変更・削除（関数・変数・スクリプト・オプション・スキル）
   - ファイルや設定の置き場所、設定のキーの変更
   - 関数やスクリプトの引数・出力の形・終了コードの変更
   - テストの補助関数や前提（一時ディレクトリの形など）の変更
3. このブランチの差分（`git diff <基点>`）が、変わる前のもの（古い名前・置き場所・キー・引数）を使っていないかを確かめる。古い置き場所に設定を書くテストのように、壊れずに意味を失うものも含める
4. 意味の食い違いも見る：同じ一覧への追加が重なる、同じものを別々に実装している、マージ先で決まった規約に合っていない

指摘には、このブランチのファイルと行、食い違うマージ先のコミット（短い sha と要約）、直し方（新しい名前や置き場所に直す。マージ先を取り込んでテストを流し直すなど）を挙げる。

次は指摘しない。

- git のマージで衝突として見つかるもの（同じ行を両方で変えただけのもの）
- マージ先の変更そのものの問題
- このブランチの変更だけで完結する一般的なバグや書き方の好み
