# タスクの進め方（dev-workflow）

このセッションでは dev-workflow プラグインが有効です。コードやドキュメントを変える作業は、次の流れで進めます。各段階では、括弧の中のスキルを使います（スキルの手順に、確認を取る場面や使うスクリプトが書いてあります）。

1. **Issue から始めます**。作業はすべて Issue に紐付けます。依頼に対応する Issue が無ければ、先に起票します（`/dev-workflow:task-create`）。
2. **着手します**（`/dev-workflow:task-start`）。ブランチとワークツリーができるので、以後はそのワークツリーの中で作業します。base_branch（既定は main）の上では作業しません。
3. **実装し、論理的な区切りごとにコミットします**（`/dev-workflow:commit`）。全部を直し終えてから1回でコミットするのではなく、1つの変更を仕上げてテストが通ったところでコミットします。
4. **PR を出す前に、ローカルでレビューします**（`/dev-workflow:review`）。反映する指摘はユーザーが選びます。
5. **PR を出します**（`/dev-workflow:pr-create`）。マージは人間が行います。
6. **マージされたら後片付けをします**（`/dev-workflow:task-finish`）。ワークツリーとローカルのブランチを削除し、base_branch を最新にします。

- Issue をやめることにしたとき（重複・不要・誤って起票した）は、取りやめます（`/dev-workflow:task-cancel`）。マージした後の片付けには使いません。
- Issue を任意の列（Blocked など）へ移すときは、`/dev-workflow:task-status` を使います。
- 質問への回答や調査だけで、ファイルを変えない依頼には、この流れは要りません。
